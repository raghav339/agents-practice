# Agents Practice

A collection of small Python projects for learning how to build **LLM agents with tool calling, memory, planning, and conversation summarization**.

The repository demonstrates different approaches to connecting an LLM to Python functions and external APIs using the OpenAI-compatible API provided by Groq.

## ✨ What This Project Covers

- LLM-based tool calling
- Manual tool execution
- ReAct-style agent loops
- Structured JSON responses from an LLM
- Multi-step planning before tool execution
- Persistent JSON-based memory
- Wikipedia API integration
- Weather API integration
- Mathematical expression evaluation
- Conversation-context compression after multiple turns

### `WeatherAndMathAgent.py`

A simple agent that demonstrates LLM tool calling with two tools:

- `get_weather(city)` — retrieves current weather information using WeatherAPI.
- `calculate(expression)` — evaluates mathematical expressions.

The user can choose between a weather query and a mathematical calculation.

### `CodingAndWikiAgent.py`

Demonstrates an LLM agent that can use tools such as code-related functionality and Wikipedia search. It follows the standard tool-calling loop:

1. Send the user request and available tools to the model.
2. Detect tool calls returned by the model.
3. Execute the requested Python function.
4. Send the tool result back to the model.
5. Continue until the model produces a final response.

### `manualToolCall.py`

Demonstrates **manual tool calling** using structured JSON generated by the model.

The agent supports:

- Wikipedia search
- Saving notes
- Retrieving notes
- Mathematical calculations

Instead of using the provider's automatic tool execution mechanism, the Python program interprets the model's JSON response and executes the requested function itself.

### `manualToolCallWithPlan.py`

An extension of the manual tool-calling approach that introduces **planning before execution**.

The model first produces a plan such as:

```json
{
  "plans": {
    "step1": "Search for the required information",
    "step2": "Process the result",
    "step3": "Provide the final answer"
  },
  "why": "These steps are required to answer the question."
}
```

The program then allows the agent to execute the planned actions one at a time.

### `summarizeContextAfterNturns.py`

Builds on the planning-based agent and adds **conversation summarization**.

After a configurable number of iterations, the current conversation is compressed into a summary containing:

- The original user request
- Tools that were actually called
- Important tool results
- Remaining work

The summary is then used as context so the agent can continue without keeping the entire previous conversation.

### `memory.json`

A simple persistent JSON store used by the memory tools.

The `save_note()` function writes information to this file, while `get_note()` retrieves previously saved information.

Example:

```json
{
  "exam_date": "20th April",
  "favorite_subject": "physics"
}
```

## 🧠 Agent Architecture

The main agent implementations follow this general flow:

```text
User
  │
  ▼
LLM
  │
  ├── Final answer ───────────────► User
  │
  └── Tool request
          │
          ▼
     Python function
          │
          ▼
      Tool result
          │
          ▼
         LLM
          │
          └── Continue / Final answer
```

The planning version adds an additional stage:

```text
User
  │
  ▼
Create Plan
  │
  ▼
Execute Tool 1
  │
  ▼
Execute Tool 2
  │
  ▼
Execute Tool N
  │
  ▼
Final Answer
```

## 🚀 Getting Started

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd agents-practice
```

### 2. Create a virtual environment

Windows:

```bash
python -m venv venv
venv\Scripts\activate
```

macOS/Linux:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Install dependencies

Install the dependencies listed in `requirements.txt`:

```bash
pip install -r requirements.txt
```

### 4. Configure API keys

The project requires API credentials for the LLM provider and, for the weather example, WeatherAPI.

**Do not commit API keys to Git.**

A safer approach is to store credentials in environment variables:

Windows PowerShell:

```powershell
$env:GROQ_API_KEY="your-groq-api-key"
$env:WEATHER_API_KEY="your-weather-api-key"
```

macOS/Linux:

```bash
export GROQ_API_KEY="your-groq-api-key"
export WEATHER_API_KEY="your-weather-api-key"
```

Then update the Python scripts to read the variables with:

```python
import os

API_KEY = os.getenv("GROQ_API_KEY")
WEATHER_API_KEY = os.getenv("WEATHER_API_KEY")
```

> **Security warning:** If the API keys currently present in the source code are real, revoke/rotate them and replace them with environment variables before pushing the project to GitHub.

## 📚 Learning Goals

This repository is intended as practice for understanding the building blocks behind modern AI agents:

1. Calling an LLM from Python
2. Defining tools with JSON schemas
3. Detecting tool calls
4. Executing Python functions based on model output
5. Returning tool results to the model
6. Building ReAct-style loops
7. Adding explicit planning
8. Maintaining persistent memory
9. Compressing long conversations
10. Combining multiple tools in a single agent workflow

## ⚠️ Notes and Limitations

This is a learning/practice project rather than a production-ready agent framework.

Potential areas for improvement include:

- Moving all secrets to environment variables
- Replacing `eval()` with a safer math-expression parser
- Adding stronger error handling
- Validating model-generated JSON with schemas
- Handling multiple tool calls more robustly
- Adding logging and structured tracing
- Adding automated tests
- Separating configuration, tools, and agent logic into modules
- Adding a `requirements.txt`
- Improving memory storage beyond a JSON file
